## 5a. Как отправить пост с кнопкой — по шагам

Нужно только для варианта Б. Кнопка под постом — это поле `reply_markup` у
сообщения, и поставить её можно единственным способом: отправить пост ботом,
который состоит администратором канала. В интерфейсе Telegram кнопку к посту
прикрепить нечем — такого пункта в меню публикации нет.

**Решение принимается до публикации.** Бот умеет менять только свои
сообщения: к посту, опубликованному руками, кнопку потом не добавить. Переделать
— значит удалить пост и отправить заново, потеряв дату, просмотры и реакции.

> **Все команды ниже выполняются на сервере, в окне SSH.** Не в командной
> строке Windows: там `$TOKEN` не переменная, а просто семь символов, и они
> уедут в адрес запроса как есть. Шаг 2 — подключение, и до него не стоит
> набирать ничего из последующих шагов.

### Что подставить — выпишите заранее

Две строки. Дальше в командах они обозначены заглавными буквами:

| В командах | Что это | Где взять |
| --- | --- | --- |
| `ССЫЛКА_НА_ПРИЛОЖЕНИЕ` | `https://t.me/<бот>/<короткое_имя>` | @BotFather, команда `/newapp` |
| `@ВАШ_КАНАЛ` | @username канала, вместе с собакой | настройки канала |

### Шаг 1. Добавить бота администратором канала

1. Откройте канал → «Управление каналом» → «Администраторы».
2. «Добавить администратора» → найдите своего бота по его @username.
3. Включите два права: **«Публикация сообщений»** и **«Изменение сообщений»**.
   Остальные выключите.
4. Сохраните.

Без этого шага всё, что ниже, вернёт ошибку.

### Шаг 2. Подключиться к серверу

На своём компьютере, в PowerShell:

```

```

Все следующие шаги — в этом же окне. Переменные живут только внутри одного
подключения: закроете окно или подключитесь заново — придётся повторить шаг 4.

### Шаг 3. Сделать рабочую папку

```bash
mkdir -p /root/posts
cd /root/posts
```

Почему не в каталоге приложения: `/opt/vk-rideshare/app` — это рабочая копия
репозитория, и посторонние файлы в ней будут мешаться при каждом `git pull`.

### Шаг 4. Положить токен в переменную

```bash
TOKEN=$(sed -n 's/^TELEGRAM_BOT_TOKEN=//p' /opt/vk-rideshare/app/.env | tr -d '"\r ')
echo "длина токена: ${#TOKEN}"
```

Вторая строка печатает только длину, сам токен на экран не попадает. Должно
получиться около 46 символов.

- **Напечатало 0** — в `.env` нет строки `TELEGRAM_BOT_TOKEN=`. Проверьте:
  `grep -c TELEGRAM_BOT_TOKEN /opt/vk-rideshare/app/.env`.
- **Значение в одинарных кавычках** — команда их не снимет, уберите в файле
  руками. Двойные и пробелы снимаются сами.

Проверить, что токен рабочий:

```bash
curl -sS "https://api.telegram.org/bot$TOKEN/getMe"
```

В ответе должно быть `"ok":true` и имя вашего бота. Токен в ответ не попадает,
эту строку можно показывать кому угодно.

### Шаг 4а. Если вместо ответа — «Could not connect to server»

```
curl: (28) Failed to connect to api.telegram.org:443 after 21113 ms
```

**У вас это уже проверено, и ответ отрицательный.** Адрес не отвечает ни с
домашней сети, ни с сервера в Уфе: 141 секунда ожидания и то же самое
соединение, которое не устанавливается. Токен при этом читается правильно —
длина 46, то есть дело не в нём. Исходящий 443 с сервера жив — `vk.com`
отвечает кодом 302, — значит блокировка точечная, а не «сервер без интернета».

Вывод простой: **публикуйте вариант А, без кнопки.** Остальное в этом шаге
оставлено на случай, если вы смените хостинг или появится прокси.

### Что проверено и что осталось проверить

`getent hosts api.telegram.org` вернул **только IPv6-адрес**, и адрес
настоящий: `2001:67c:4e8::/48` — диапазон самого Telegram. Подмены DNS нет,
менять серверы имён бессмысленно.

Проверялась версия, что дело не в блокировке, а в IPv6 без маршрута наружу —
на дешёвых VPS это обычное дело, и выглядело бы точно так же. Не подтвердилась:

```bash
curl -4 -sS -m 15 "https://api.telegram.org/bot$TOKEN/getMe"
curl: (28) Connection timed out after 15002 milliseconds
```

Запрос принудительно по IPv4 упёрся в тот же таймаут. Значит соединения нет ни
по одному протоколу, а DNS при этом отвечает честно. Это блокировка.

**Итог проверки — по порядку, чтобы не возвращаться:**

| Что проверено | Результат |
| --- | --- |
| Токен читается из `.env` | Да, длина 46 |
| Исходящий 443 с сервера вообще | Жив, `vk.com` отвечает 302 |
| DNS честный | Да, адрес из диапазона Telegram |
| Соединение по IPv6 | Таймаут |
| Соединение по IPv4 (`-4`) | Таймаут |

Вывод: `api.telegram.org` недоступен и с домашней сети, и с сервера.
**Публикуйте вариант А, без кнопки.**

### Главное: запрос не обязан уходить с сервера

Отправка поста — один HTTPS-запрос. Bot API не смотрит, откуда он пришёл: ни
привязки к адресу, ни к машине нет. Сервер в этой схеме не нужен вовсе — он
появился в инструкции только потому, что там лежит токен.

Значит, кнопка доступна, если найдётся **любая** сеть, откуда
`api.telegram.org` открыт. Проверить сеть можно за десять секунд: откройте в
браузере `https://api.telegram.org` без всякого токена. Открылась страница
(пусть даже с текстом про неверный метод) — адрес доступен, этой сетью можно
пользоваться.

Что подходит, по возрастанию возни:

1. **Другая сеть под рукой** — мобильный интернет другого оператора, рабочий
   компьютер, ноутбук у знакомого. Проверяется страницей выше.
2. **Браузерная консоль в облаке** — например, Google Cloud Shell: бесплатна,
   открывается в браузере, `curl` там есть. Ставить ничего не нужно. Подробно
   ниже.
3. **VPN на своём компьютере** — включить, отправить один запрос, выключить.

Во всех трёх случаях порядок тот же, что в шагах 5–8, с одной разницей: токен
придётся вставить руками, потому что `.env` остался на сервере. Тогда не
набирайте его в адресной строке браузера — только в терминале, и лучше в виде
переменной:

```bash
TOKEN=сюда_вставить_токен
curl -sS "https://api.telegram.org/bot$TOKEN/sendMessage" \
  -H 'Content-Type: application/json' -d @post.json
```

**4. Репетиция — отправить пост себе в личку**

Пропускать не стоит: ошибку в канале видно всем, а в личке — только вам.

Сначала нужен ваш числовой идентификатор в Telegram. Два способа, оба
занимают полминуты.

**Проще всего:** в Telegram напишите боту `@userinfobot` — он ответит вашим
номером, и ничего разбирать не придётся.

**Если не хочется трогать чужого бота:** напишите своему боту любое сообщение
прямо сейчас — «привет» подойдёт, — и в консоли выполните:

```bash
TOKEN=сюда_вставить_токен
curl -sS -m 15 "https://api.telegram.org/bot$TOKEN/getUpdates" | python3 -c "import sys,json;r=json.load(sys.stdin).get('result',[]);ids={u[k]['chat']['id'] for u in r for k in u if isinstance(u.get(k),dict) and 'chat' in u[k]};print('\n'.join(map(str,ids)) or 'пусто')"
```

Команда напечатает одно число — это он и есть. Разбирать JSON руками не нужно.

Напечатало `пусто` — значит бот не получил от вас ни одного свежего сообщения:
Telegram отдаёт только непрочитанные обновления за последние сутки. Напишите
боту ещё раз и повторите команду.

Дальше отправьте копию поста себе:

```bash
sed 's|"chat_id": "[^"]*"|"chat_id": "ВАШ_НОМЕР"|' post.json > test.json
curl -sS -m 15 "https://api.telegram.org/bot$TOKEN/sendMessage" \
  -H 'Content-Type: application/json' -d @test.json
```

Посмотрите в Telegram: текст, переносы строк, кнопка. Нажмите кнопку —
приложение должно открыться.

**5. Отправить в канал**

```bash
curl -sS -m 15 "https://api.telegram.org/bot$TOKEN/sendMessage" \
  -H 'Content-Type: application/json' -d @post.json
```

В ответе ищите `"ok":true` и `"message_id"` с числом — число запишите, по нему
потом меняется кнопка.

**6. Закрепить**

Руками, в Telegram: долгое нажатие на пост → «Закрепить» → «Уведомить
подписчиков».

**7. Прибраться за собой**

```bash
rm -f post.json test.json
cat /dev/null > ~/.bash_history
history -c
```

Домашний каталог облачной консоли живёт довольно долго, поэтому файл с
`chat_id` и история команд с токеном там останутся, если их не убрать.

**8. Сменить токен — по желанию, но лучше сделать**

Токен побывал на чужой машине. Отозвать его просто: @BotFather → `/revoke` →
выбрать бота → получить новый. Затем на сервере вписать новый в
`/opt/vk-rideshare/app/.env` и перезапустить службу API. Старый токен после
этого не стоит ничего, и беспокоиться о нём больше не нужно.

**Насколько это разовая история.** Закреп с кнопкой отправляется один раз.
Но и каждый следующий пост с кнопкой придётся слать оттуда же, и `message_id`
для правок надо будет сохранять. Если посты с кнопкой нужны регулярно, это
перестаёт быть удобным, и тогда разговор уже про хостинг.

### Остальные пути

Сменить хостинг на площадку, откуда адрес открыт, отправлять посты через
прокси (`--proxy`, см. ниже) или через «разблокирующий» DNS — о нём ниже.

### Попытка через другой DNS

Обычный резолвер — 1.1.1.1, 8.8.8.8 — здесь не поможет: наш DNS и так отвечает
честно, настоящим адресом Telegram, а не устанавливается само соединение.

Другое дело **разблокирующий DNS** (их называют smart DNS). Такой сервис на
заблокированные домены отдаёт не настоящий адрес, а свой собственный, и трафик
идёт через его сервер. Для `api.telegram.org` это может сработать — и это
единственный случай, когда смена DNS имеет смысл.

**Сначала проверка, без изменения системы.** Узнаём, какой адрес отдаёт
нужный резолвер:

```bash
apt-get install -y dnsutils
dig @АДРЕС_ВАШЕГО_DNS api.telegram.org A +short
getent ahostsv4 api.telegram.org
```

- Адреса совпали или оба из `149.154.x.x` — это обычный резолвер, смена DNS
  ничего не даст. Дальше не идите.
- Адрес другой, из чужого диапазона — это и есть разблокирующий DNS, пробуем.

Проверяем соединение прямо с этим адресом, по-прежнему ничего не меняя в
системе:

```bash
curl -4 -sS -m 15 --resolve api.telegram.org:443:ПОЛУЧЕННЫЙ_АДРЕС \
  "https://api.telegram.org/bot$TOKEN/getMe"
```

Пришло `"ok":true` — работает. Дальше два пути: добавлять `--resolve` к
каждому запросу (ничего не меняется в системе, но надо помнить) или прописать
DNS на сервере.

**Прописать DNS на сервере.** В Ubuntu 24.04 этим занимается
`systemd-resolved`, и `/etc/resolv.conf` править руками нельзя — он
перезаписывается. Правильное место — отдельный файл настройки:

```bash
mkdir -p /etc/systemd/resolved.conf.d
cat > /etc/systemd/resolved.conf.d/dns.conf <<'EOF'
[Resolve]
DNS=АДРЕС_ВАШЕГО_DNS
FallbackDNS=1.1.1.1 8.8.8.8
EOF
systemctl restart systemd-resolved
```

Проверить, что применилось, и что имена вообще продолжают разрешаться:

```bash
resolvectl status | grep -A3 'DNS Servers'
getent ahostsv4 api.telegram.org
getent ahostsv4 github.com
```

`FallbackDNS` здесь не для красоты: если ваш резолвер однажды замолчит, сервер
останется без разрешения имён целиком — отвалятся `apt`, `git pull`, выкатка.
Запасной адрес это предотвращает.

**Откат, если что-то пошло не так:**

```bash
rm /etc/systemd/resolved.conf.d/dns.conf
systemctl restart systemd-resolved
```

Подключение по SSH идёт по адресу, а не по имени, поэтому даже полностью
сломанный DNS не отрежет вас от сервера — откатиться можно всегда.

**Чего не делать.** Не прописывайте чужой DNS, если не понимаете, кому он
принадлежит: резолвер видит все имена, к которым обращается сервер, и может
отвечать на них чем угодно. Для сервера с базой пользователей это не мелочь.

Это не опечатка и не фаервол сервера. Имя разрешилось, а соединение не
установилось — так выглядит блокировка на стороне сети. У российских домашних
провайдеров `api.telegram.org` недоступен; у хостинга бывает по-разному, и
проверять надо именно на сервере.

**На работу приложения это никак не влияет.** Сервер к `api.telegram.org` не
обращается вообще: подпись `initData` проверяется на месте, своим ключом
(`apps/api/src/lib/telegram-init-data.ts`), и наружу за этим ходить незачем.
Недоступен этот адрес только для отправки постов ботом.

Если и с сервера не соединяется — три пути, по убыванию разумности.

**1. Опубликовать вариант А, без кнопки.** Ссылка стоит в тексте поста,
публикуется руками из самого Telegram, наружу ходить не нужно вовсе. Теряется
кнопка — и только она; текст в `01-pinned.md` написан так, что без кнопки он
полон. Это рабочее решение, а не отступление.

**2. Сторонний бот-постовщик** (@ControllerBot и подобные). Запросы к Telegram
делает их сервер, вы общаетесь с ботом внутри Telegram, и блокировка вашей
сети роли не играет. Цена — права администратора вашего канала у чужого бота:
он сможет публиковать и удалять посты от имени канала. Решать вам, но
собственный бот для этого уже есть, и отдавать канал чужому — плата именно за
обход блокировки, а не за удобство.

**3. Отправить запрос через прокси.** Если есть рабочий прокси или VPN:

```bash
curl -sS --proxy socks5h://АДРЕС:ПОРТ "https://api.telegram.org/bot$TOKEN/getMe"
```

Тот же `--proxy` добавляется и к `sendMessage` на шаге 9. Прокси нужен только
на время отправки: ни приложению, ни серверу он постоянно не требуется.

Чего делать не стоит: прописывать прокси в настройки всего сервера ради
одного запроса раз в неделю.

### Шаг 5. Создать файл поста

Одна вставка. Подставить нужно только две верхние строки — остальное трогать
не надо. Выделите блок целиком, от `APP_URL` до `JSON`, вставьте и нажмите
Enter:

```bash
APP_URL="https://t.me/вашбот/вашеприложение"
CHANNEL="@нужный_канал"

cat > /root/posts/post.json <<JSON
{
  "chat_id": "$CHANNEL",
  "text": "По пути — попутчики между Оренбургом, Соль-Илецком и Акбулаком.\n\nВодители публикуют поездки, пассажиры откликаются. Цена за место 500–850 ₽, её назначает автор. Договариваетесь напрямую — в сообщениях или по телефону.\n\nКак начать:\n1. Нажмите кнопку под этим постом.\n2. Посмотрите, кто уже едет, или создайте свою поездку.\n3. Откликнитесь — автор увидит заявку и ответит.\n\nСтавить ничего не нужно, приложение открывается прямо в Telegram.",
  "disable_web_page_preview": true,
  "reply_markup": {
    "inline_keyboard": [
      [{ "text": "Открыть приложение", "url": "$APP_URL" }]
    ]
  }
}
JSON
```

Здесь после `<<` стоит `JSON` **без кавычек** — именно поэтому `$CHANNEL` и
`$APP_URL` подставятся. Если поставить кавычки, в файл попадут сами имена
переменных. `\n` — это перенос строки внутри поста, так и должно быть
написано, двумя знаками; подстановка его не трогает.

Текст здесь тот же, что в `01-pinned.md`, вариант Б.

**Если команда запускается не на сервере** — в облачной консоли или на другом
компьютере, — замените `/root/posts/post.json` на просто `post.json`, и файл
ляжет в текущий каталог. Папки `/root/posts` там может и не быть.

### Шаг 6. Проверить файл до отправки

```bash
python3 -m json.tool /root/posts/post.json > /dev/null && echo "JSON в порядке"
grep -n 'вашбот\|нужный_канал' /root/posts/post.json || echo "заглушек не осталось"
```

Первая команда ловит сломанные кавычки и запятые, вторая — забытую подстановку
в двух верхних строках.

Посмотреть, что получилось целиком:

```bash
cat /root/posts/post.json
```

Если файл не нашёлся (`No such file or directory`), значит шаг 5 не выполнялся
или выполнялся в другом каталоге. Путь в командах пишите целиком, от `/root`:
команда ищет файл там, где вы сейчас находитесь, а не там, где он создавался.

### Шаг 7. Репетиция — отправить пост себе в личку

Шаг не обязательный, но он показывает пост ровно таким, каким его увидят в
канале, и ошибку можно исправить до публикации.

1. В Telegram откройте диалог со своим ботом и нажмите «Начать».
2. На сервере посмотрите, какой у вас идентификатор:

```bash
curl -sS "https://api.telegram.org/bot$TOKEN/getUpdates" | python3 -m json.tool | grep -A6 '"chat"'
```

   Нужен `"id"` в блоке, где `"type": "private"`. Это число из девяти-десяти
   цифр.

3. Сделайте копию поста с этим числом вместо канала и отправьте:

```bash
sed 's|"chat_id": "[^"]*"|"chat_id": "ВАШЕ_ЧИСЛО"|' /root/posts/post.json > /root/posts/test.json
curl -sS "https://api.telegram.org/bot$TOKEN/sendMessage" -H 'Content-Type: application/json' -d @/root/posts/test.json
```

4. Посмотрите в Telegram: текст, перенос строк, кнопка. Нажмите кнопку —
   приложение должно открыться.

### Шаг 8. Отправить в канал

```bash
curl -sS "https://api.telegram.org/bot$TOKEN/sendMessage" -H 'Content-Type: application/json' -d @/root/posts/post.json
```

В ответе — одна длинная строка. В ней должно быть `"ok":true`, а в начале —
`"message_id":` и число. **Запишите это число**: по нему потом можно поменять
кнопку, не трогая текст.

### Шаг 9. Закрепить

Руками, в самом Telegram: долгое нажатие на пост → «Закрепить» → с галочкой
«Уведомить подписчиков».

### Если вместо `"ok":true` пришла ошибка

| Что в ответе | Что это значит |
| --- | --- |
| `"error_code":401,"description":"Unauthorized"` | Токен не тот или обрезан. Вернитесь к шагу 4 и посмотрите длину |
| `"Bad Request: chat not found"` | @username канала написан неверно, или забыта собака, или бот не админ |
| `"Forbidden: bot is not a member of the channel chat"` | Бот не добавлен администратором — шаг 1 |
| `"Bad Request: not enough rights to send text messages to the chat"` | Бот админ, но без права «Публикация сообщений» |
| `"Bad Request: BUTTON_URL_INVALID"` | В `url` осталась заглушка или ссылка без `https://` |
| `"Bad Request: message text is empty"` | Сломан JSON — шаг 6 это ловит |
| `curl: option -d: error encountered when reading a file` | Файла нет по этому пути. Путь к `post.json` пишите целиком, от `/root` |
| `curl: (3) URL using bad/illegal format` | Переменная `TOKEN` пустая: новое подключение к серверу, шаг 4 заново |
| `curl: (28) Failed to connect to api.telegram.org:443` | Адрес недоступен из вашей сети — шаг 4а |
| Ничего не возвращается, команда висит | С сервера закрыт исходящий 443 |

**Канал закрытый, без @username.** Тогда вместо `"@канал"` нужен числовой
идентификатор вида `-100…`. Добавьте бота админом, напишите в канал любое
сообщение и посмотрите `getUpdates` — идентификатор будет там, в блоке
`"chat"` с `"type": "channel"`.

### Как потом поменять кнопку

Текст останется прежним, поменяется только кнопка. Подставьте `message_id` из
шага 8:

```bash
curl -sS "https://api.telegram.org/bot$TOKEN/editMessageReplyMarkup" \
  -H 'Content-Type: application/json' \
  -d '{"chat_id":"@нужный_канал","message_id":123,"reply_markup":{"inline_keyboard":[[{"text":"Новая подпись","url":"https://t.me/вашбот/вашеприложение"}]]}}'
```

Если менять и текст — метод `editMessageText`, и в нём **передавайте
`reply_markup` вместе с текстом**: иначе кнопка может пропасть. Проверьте это
на тестовом сообщении себе в личку, прежде чем править пост в канале.

### Что знать про сами кнопки

- **Тип кнопки в канале — только `url`.** Кнопка типа `web_app` работает лишь
  в приватном чате с ботом; в канал её поставить нельзя. Поэтому кнопка,
  открывающая мини-приложение, делается обычной ссылкой на
  `t.me/<бот>/<короткое_имя>`.
- **Значок в углу кнопки Telegram рисует сам** — у ссылок, ведущих за пределы
  чата. Управлять им нельзя, и в JSON для него ничего не задаётся.
- **Раскладка задаётся вложенностью.** `inline_keyboard` — массив рядов, ряд —
  массив кнопок. Одна кнопка во всю ширину это `[[ {...} ]]`; две в ряд —
  `[[ {...}, {...} ]]`; две друг под другом — `[[{...}], [{...}]]`.
- **Одна кнопка сильнее двух.** Выбор из двух действий под постом — это
  задержка на размышление там, где нужен один шаг.

### Про безопасность токена

Токен ни разу не вводится руками и не попадает ни в один файл: он читается из
`.env` в переменную и подставляется оболочкой. В истории команд остаётся
`$TOKEN`, а не значение. По той же причине не открывайте такой запрос в
браузере — адресная строка запоминается вместе с токеном, и чистить её потом
придётся вручную.

Файлы `post.json` и `test.json` токена не содержат, их можно хранить и
переиспользовать.

Если своего бота держать не хочется, то же самое делают сторонние
боты-постовщики. Цена вопроса — права администратора вашего канала у чужого
бота; при живом собственном боте это риск без выигрыша.

## Как считались символы

Во всех файлах длина указана в кодовых единицах UTF-16 — так считает сам
Telegram, и в тех же единицах заданы смещения в `entities`. Для русского
текста это ровно число символов; эмодзи из верхних плоскостей занимает две
единицы вместо одной. Пересчитать любой текст можно так:

```bash
python3 -c "import sys;t=sys.stdin.read().rstrip(chr(10));print(sum(2 if ord(c)>0xFFFF else 1 for c in t))" < текст.txt
```

Длина, указанная в каждом файле, — это длина текста между линиями `---`,
посчитанная этой же формулой.

# Поиск попутчиков — VK Mini App

Мини-приложение ВКонтакте: пользователь создаёт поездку или находит чужую
по маршруту и дате, откликается на неё, договаривается с водителем и
оставляет отзыв после поездки.

```
apps/web        React 18 + TypeScript + Vite + VKUI
apps/api        Fastify + Prisma + Postgres + Zod
packages/shared Справочник городов и Zod-контракт API (общий для обоих)
```

---

## Как это устроено

**Авторизация — ядро приложения.** ВКонтакте передаёт мини-приложению
launch-параметры (`vk_user_id`, `vk_app_id`, `vk_ts`, `sign` и прочие `vk_*`)
в query-строке. Фронтенд запоминает **исходную** строку и шлёт её заголовком
`X-Launch-Params` при каждом запросе к API.

Бэкенд на каждом запросе берёт параметры с префиксом `vk_`, сортирует по
ключу, собирает query-строку, считает от неё HMAC-SHA256 на защищённом ключе
приложения, кодирует в base64url без паддинга и сравнивает с `sign`
константным по времени сравнением. Несовпадение — `401`. Параметры с `vk_ts`
старше 24 часов — тоже `401`.

**Защищённый ключ живёт только в переменной окружения бэкенда.** На фронтенд
он не попадает, в репозиторий не коммитится, в логи не пишется (заголовок
`X-Launch-Params` вырезается из журнала Fastify).

Сессий и куки нет намеренно: подпись проверяется на каждом запросе,
состояние на сервере не нужно.

## Шаг 1. Создать приложение в VK

1. Откройте <https://dev.vk.com/> и создайте новое приложение типа
   **VK Mini App**.
2. В настройках приложения найдите два значения:
   - **ID приложения** — число, которое видно и в адресе `vk.com/app<ID>`;
   - **Защищённый ключ** (service/secret key) — им подписываются
     launch-параметры.
3. В настройках укажите адрес, по которому раздаётся фронтенд:
   для локальной разработки — адрес dev-сервера Vite, для продакшена —
   выданный хостингом VK Mini Apps домен.

> Точные названия полей в кабинете разработчика ВКонтакте со временем
> меняются. Сверяйтесь с актуальной документацией на dev.vk.com —
> из окружения, где писался этот код, сайт был недоступен, поэтому здесь
> описан смысл настроек, а не расположение кнопок.

## Шаг 2. Переменные окружения

Все переменные — в одном файле `.env` в корне репозитория. Он в `.gitignore`;
в репозитории лежит только `.env.example` с пустыми значениями.

```bash
cp .env.example .env
```

| Переменная | Где нужна | Что это |
|---|---|---|
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `POSTGRES_PORT` | docker-compose | Параметры контейнера с Postgres |
| `DATABASE_URL` | API, Prisma | Строка подключения, например `postgresql://rideshare:rideshare@localhost:5432/vk_rideshare?schema=public` |
| `API_PORT`, `API_HOST` | API | Где слушает бэкенд (по умолчанию `3000` / `0.0.0.0`) |
| `NODE_ENV` | API | `development` \| `test` \| `production` |
| `CORS_ORIGIN` | API | Домен фронтенда, через запятую при нескольких |
| `VK_APP_ID` | API | ID приложения из кабинета ВКонтакте |
| **`VK_APP_SECRET`** | **только API** | **Защищённый ключ. На фронтенд не попадает никогда.** Обязателен при `NODE_ENV=production` — без него бэкенд не стартует |
| `VK_MOCK_LAUNCH_PARAMS` | API, только dev | Моковые launch-параметры для запуска вне ВКонтакте. При `NODE_ENV=production` игнорируется |
| `VITE_API_BASE_URL` | фронтенд | Адрес API, например `http://localhost:3000/api` |

> Всё, что начинается с `VITE_`, попадает в бандл фронтенда и видно любому
> пользователю. Секретов там быть не может по определению.

## Шаг 3. Запуск локально

```bash
npm install                 # установит зависимости и соберёт packages/shared
docker compose up -d        # Postgres 16 на порту из POSTGRES_PORT
npm run db:push             # накатить схему (или npm run db:migrate)
npm run db:seed             # 10 пользователей, 36 поездок, отклики и отзывы
npm run dev                 # API на :3000 и фронтенд на :5173
```

Откройте <http://localhost:5173/>.

`npm run dev` поднимает оба процесса в одном терминале. На Windows запускайте
их раздельно: `npm run dev:api` и `npm run dev:web`.

### Чтобы приложение открывалось вне ВКонтакте

Вне фрейма ВКонтакте браузер не получает launch-параметров, и API отвечал бы
`401`. Для разработки бэкенд умеет подставлять параметры из
`VK_MOCK_LAUNCH_PARAMS`.

Важно: **проверка подписи при этом не отключается.** Бэкенд пересобирает
моковую строку, проставляет свежий `vk_ts` и подписывает её локальным
`VK_APP_SECRET` — дальше она идёт по тому же пути, что и настоящая. Ветки
«пропустить проверку» в коде нет.

Минимально достаточно указать пользователя:

```dotenv
VK_MOCK_LAUNCH_PARAMS=vk_user_id=1000001&vk_app_id=51234567&vk_platform=desktop_web
```

`vk_user_id` — любой из сида (`1000001`…`1000010`), от его имени вы и войдёте.

Нужна полная подписанная строка (например, чтобы открыть приложение от имени
другого пользователя прямо из адресной строки) — сгенерируйте её:

```bash
npm run gen:launch-params -w @vk-rideshare/api -- --user 1000003
```

Полученную строку можно либо положить в `VK_MOCK_LAUNCH_PARAMS`, либо
дописать к адресу: `http://localhost:5173/?<строка>`.

**В продакшене этот путь выключен двумя независимыми предохранителями:**
конфигурация обнуляет `VK_MOCK_LAUNCH_PARAMS` при `NODE_ENV=production`,
и хук авторизации в эту ветку не заходит, если `isProduction`. Оба покрыты
тестами (`apps/api/test/auth.test.ts`).

## API

Все маршруты под префиксом `/api` и требуют заголовок `X-Launch-Params`.
Ошибки всегда одного вида: `{ "error": { "code": "...", "message": "..." } }`.
Фронтенд разбирает `code`, а не текст.

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/session` | Проверяет подпись, обновляет кэш профиля, возвращает его |
| `GET` | `/trips` | Лента: фильтры `from`, `to`, `date`, `role`, `priceMax`, `seatsMin`, курсорная пагинация. Только `ACTIVE` и только будущие |
| `POST` | `/trips` | Создание поездки |
| `GET` | `/trips/:id` | Детали. Все отклики видит только автор, остальные — только свой |
| `PATCH` | `/trips/:id` | Завершить или отменить, только автором |
| `POST` | `/trips/:id/requests` | Отклик |
| `GET` | `/trips/:id/reviewable` | Кому можно оставить отзыв по завершённой поездке |
| `PATCH` | `/requests/:id` | Принять или отклонить, только автором поездки |
| `GET` | `/me/trips`, `/me/requests` | Мои объявления и мои отклики |
| `POST` | `/reviews` | Отзыв |
| `GET` | `/users/:vkUserId` | Публичный профиль, рейтинг, отзывы |

Запрет на запись ограничен rate limit'ом, CORS открыт только домену из
`CORS_ORIGIN`.

### Что гарантируется транзакциями

- **Места не уходят в минус.** Принятие отклика уменьшает `seatsLeft`
  условным `UPDATE ... WHERE "seatsLeft" > 0` в одной транзакции с переводом
  отклика в `ACCEPTED`. Параллельная транзакция встаёт на блокировке строки,
  после её снятия Postgres перепроверяет условие на новой версии строки и
  возвращает `409`. Проверено тестом на пять одновременных принятий.
- **Отзыв — один раз на пару автор→адресат** и только участнику завершённой
  поездки; рейтинг пересчитывается в той же транзакции.

## Экраны

| Экран | Что на нём |
|---|---|
| **Поиск** | Фильтры (откуда, куда, дата, роль, цена, мест), карточки поездок, скелетоны, пустое состояние, подгрузка по скроллу |
| **Поездка** | Маршрут, время, цена, места, комментарий, автор с рейтингом. Гостю — «Откликнуться» с сообщением, автору — список откликов с «Принять»/«Отклонить» |
| **Создание** | Роль, маршрут, дата и время, места, цена, авто, комментарий; ошибки под полями |
| **Мои поездки** | Вкладки «Объявления», «Отклики», «Завершено» с кнопкой отзыва |
| **Профиль** | Данные из ВКонтакте, рейтинг, число поездок, отзывы |

Тема берётся из клиента ВКонтакте: приложение подписано на событие
`VKWebAppUpdateConfig` и переключает `colorScheme` в VKUI. Вне ВКонтакте
используется системная тема браузера.

### Почему кнопка «Написать» ведёт на профиль

В типах `@vkontakte/vk-bridge` нет метода, открывающего диалог с
пользователем. Выдумывать метод нельзя, поэтому кнопка ведёт на
`https://vk.com/id<vkUserId>` — диалог открывается оттуда штатными
средствами клиента. Если в API ВКонтакте появится подтверждённый способ,
менять нужно только `buildProfileUrl` в `apps/web/src/vk/bridge.ts`.

## Шаг 4. Выкатка фронтенда на хостинг VK Mini Apps

1. Соберите статику:

   ```bash
   npm run build -w @vk-rideshare/web
   ```

   Результат — `apps/web/dist`. Сборка использует относительные пути
   (`base: './'` в `vite.config.ts`), поэтому работает из любого подкаталога.

2. Перед сборкой задайте `VITE_API_BASE_URL` на боевой адрес API —
   значение вшивается в бандл на этапе сборки, а не читается в рантайме.

3. Залейте `apps/web/dist` на хостинг VK Mini Apps. ВКонтакте предоставляет
   для этого CLI (`@vkontakte/vk-miniapps-deploy`): он кладёт статику на
   выданный вам домен и разводит staging- и production-версии. Пакет в
   зависимости проекта намеренно не добавлен — это инструмент выкатки,
   а не код приложения:

   ```bash
   npx @vkontakte/vk-miniapps-deploy
   ```

   Команда попросит токен и параметры приложения при первом запуске.
   Сверьтесь с актуальной документацией на dev.vk.com: порядок авторизации
   и названия окружений там периодически меняются, а из окружения, где
   писался этот код, сайт был недоступен для проверки.

4. Бэкенд разверните отдельно (хостинг VK Mini Apps раздаёт только статику).
   Ему нужны `DATABASE_URL`, `VK_APP_SECRET`, `NODE_ENV=production` и
   `CORS_ORIGIN` с доменом, который выдал хостинг:

   ```bash
   npm run build -w @vk-rideshare/api
   npm run db:deploy -w @vk-rideshare/api   # применить миграции
   npm run start -w @vk-rideshare/api
   ```

5. В настройках приложения во ВКонтакте пропишите выданный домен как адрес
   мини-приложения.

## Чего в проекте нет намеренно

Оплаты и эквайринга, карт и геокодинга, пуш-уведомлений, админки,
мультиязычности, аналитики, CI-конфигов и Docker-образа приложения.
Города — статический справочник из ~100 крупнейших городов России в
`packages/shared/src/cities.ts`, без внешних запросов.

# Поиск попутчиков — VK Mini App

Мини-приложение ВКонтакте: пользователь создаёт поездку или находит чужую
по маршруту и дате, откликается на неё, договаривается с водителем и
оставляет отзыв после поездки.

Приложение обслуживает три города Оренбургской области и шесть направлений
между ними: **Оренбург ↔ Соль-Илецк**, **Оренбург ↔ Акбулак**,
**Акбулак ↔ Соль-Илецк**. Цена за место — от **500 до 850 ₽**, время выезда
задаётся получасовыми слотами. Все три правила проверяются и на бэкенде,
и в форме.

```
apps/web        React 18 + TypeScript + Vite + VKUI
apps/api        Fastify + Prisma + Postgres + Zod
packages/shared Справочник направлений, сетка выездов и Zod-контракт API
```

# Запуск локально

Раздел написан так, чтобы его можно было выполнять сверху вниз, ничего не
додумывая. **Настоящее приложение во ВКонтакте для локального запуска не
нужно** — оно понадобится только для выкатки (см. [«Приложение во
ВКонтакте»](#приложение-во-вконтакте)).

## Шаг 0. Что должно быть установлено

| Что | Версия | Проверить | Если нет |
|---|---|---|---|
| **Node.js** | **20.12 или новее** | `node -v` | <https://nodejs.org/> или `nvm install 22` |
| **npm** | 10 или новее | `npm -v` | Ставится вместе с Node.js |
| **Git** | любая | `git --version` | <https://git-scm.com/downloads> |
| **Postgres 16** | — | см. шаг 2 | Установщик под вашу систему; Docker не обязателен |

Почему именно 20.12: код читает `.env` встроенным `process.loadEnvFile()`,
который появился в этой версии. Отдельная библиотека для чтения `.env`
проекту не нужна. Проверялось на Node 22.

Проверка одной командой:

```bash
node -v && npm -v && git --version
```

Ожидаемый вид ответа:

```
v22.22.2
10.9.7
git version 2.43.0
```

Если `node -v` показывает `v18` или меньше — обновите Node, иначе
приложение не стартует.

## Шаг 1. Склонировать репозиторий и поставить зависимости

Сначала **перейдите в папку, куда вам разрешено писать**. Терминал часто
открывается в системном каталоге — `C:\Windows\System32` для cmd,
запущенного от имени администратора, — и клонирование туда падает с
`could not create work tree dir 'Labs': Permission denied`.

**Windows, cmd:**

```bat
mkdir %USERPROFILE%\projects
cd /d %USERPROFILE%\projects
```

**Windows, PowerShell:**

```powershell
mkdir $HOME\projects -Force
cd $HOME\projects
```

**macOS и Linux:**

```bash
mkdir -p ~/projects
cd ~/projects
```

Проверьте, что вы действительно там: `cd` без аргументов в cmd (или `pwd`
в PowerShell, macOS и Linux) должен показать вашу папку, а не
`C:\Windows\System32` и не корень диска.

Теперь клонируйте:

```bash
git clone https://github.com/noxfor63/Labs.git
cd Labs
git checkout claude/vk-rideshare-mini-app-qqbdhb
npm install
```

> Запускать терминал от имени администратора для этого проекта не нужно —
> ни для клонирования, ни для установки зависимостей, ни для запуска.

`npm install` делает **три** вещи, а не одну:

1. ставит зависимости всех трёх пакетов монорепозитория сразу
   (npm workspaces — отдельно в `apps/api` и `apps/web` заходить не нужно);
2. связывает `packages/shared` с обоими приложениями;
3. собирает `packages/shared` в `packages/shared/dist` — это делает скрипт
   `prepare`. Без него `apps/api` и `apps/web` не найдут общие типы.

Занимает 40–90 секунд. Успешное завершение выглядит так:

```
added 494 packages in 43s
```

**Проверка, что шаг удался** — каталог `packages/shared/dist` существует и
не пуст:

```bash
ls packages/shared/dist
# cities.d.ts  cities.js  domain.d.ts  domain.js  index.d.ts  index.js  ...
```

Если каталога нет, соберите вручную: `npm run build -w @vk-rideshare/shared`.

## Шаг 2. Поднять Postgres

Нужен Postgres 16. Выберите **один** из трёх вариантов — приложению
безразлично, откуда база.

> **Базу создавать руками не нужно.** Если её нет, `npm run db:push` из
> шага 4 создаст её сам и напишет `PostgreSQL database vk_rideshare
> created`. Достаточно, чтобы сам сервер Postgres был запущен и
> `DATABASE_URL` был правильным.

### Вариант А — Postgres прямо в системе (работает везде)

Не требует ни Docker, ни виртуализации. Самый надёжный путь, если
Docker Desktop не запускается.

**Windows.** Скачайте установщик с
<https://www.postgresql.org/download/windows/> (сборка EDB), поставьте
версию 16. В мастере:

1. Компоненты: достаточно **PostgreSQL Server** и **Command Line Tools**,
   pgAdmin по желанию.
2. Пароль для пользователя `postgres` — **запомните его**, он пойдёт в
   `DATABASE_URL`.
3. Порт оставьте `5432`.
4. Stack Builder в конце можно закрыть, он не нужен.

Сервер ставится службой и стартует сам при загрузке Windows. Проверить,
что он работает: «Службы» → `postgresql-x64-16` → состояние
«Выполняется».

**macOS:**

```bash
brew install postgresql@16
brew services start postgresql@16
```

**Linux (Debian/Ubuntu):**

```bash
sudo apt install postgresql-16
sudo systemctl start postgresql
```

**Строка подключения для шага 3** — с вашим пользователем и паролем:

```
postgresql://postgres:ВАШ_ПАРОЛЬ@localhost:5432/vk_rideshare?schema=public
```

На macOS и Linux пользователь обычно совпадает с вашим системным именем,
а пароля может не быть вовсе — тогда `postgresql://localhost:5432/vk_rideshare?schema=public`.

### Вариант Б — через Docker

В репозитории лежит готовый `docker-compose.yml`.

```bash
docker compose up -d --wait
```

Флаг `--wait` важен: без него команда возвращает управление сразу, а база
ещё несколько секунд поднимается, и следующий шаг падает с ошибкой
подключения. С `--wait` команда ждёт, пока healthcheck станет зелёным.

Проверка:

```bash
docker compose ps
# NAME               IMAGE               STATUS
# vk-rideshare-db    postgres:16-alpine  Up 12 seconds (healthy)
```

Контейнер поднимается с такими параметрами (это значения по умолчанию из
`docker-compose.yml`, они применяются, если `POSTGRES_*` в `.env` пустые):

| Параметр | Значение |
|---|---|
| пользователь | `rideshare` |
| пароль | `rideshare` |
| база | `vk_rideshare` |
| порт на хосте | `5432` |

**Строка подключения для шага 3:**

```
postgresql://rideshare:rideshare@localhost:5432/vk_rideshare?schema=public
```

> **Docker на Windows требует виртуализации.** Если Docker Desktop пишет
> «Virtualization support not detected» или «failed to connect to the
> docker API at npipe:…», см. таблицу ошибок ниже — и не тратьте время,
> берите вариант А, он ничем не хуже.

> Если порт 5432 на машине уже занят другим Postgres — задайте в `.env`
> `POSTGRES_PORT=5433` и укажите этот же порт в `DATABASE_URL`.

### Вариант В — готовый Postgres: корпоративный или облачный

Подойдёт любой доступный сервер Postgres 16, в том числе бесплатный
облачный. Ничего ставить локально не нужно — возьмите строку подключения
и вставьте её в `DATABASE_URL`. Если база на сервере ещё не создана и у
вашего пользователя есть право `CREATEDB`, шаг 4 создаст её сам; если
права нет — попросите создать пустую базу, остальное сделает миграция.

## Шаг 3. Создать файл `.env`

Все настройки — в **одном** файле в корне репозитория. Он в `.gitignore` и
в репозиторий не попадает; рядом лежит шаблон `.env.example` с одними
только именами переменных.

```bash
cp .env.example .env
```

Теперь откройте `.env` и заполните **три** строки. Остальные можно оставить
пустыми — пустое значение считается «не задано», и подставляется значение
по умолчанию.

### 3.1. `DATABASE_URL` — строка подключения из шага 2

```dotenv
DATABASE_URL=postgresql://rideshare:rideshare@localhost:5432/vk_rideshare?schema=public
```

Разбор по частям:

```
postgresql://  rideshare : rideshare @ localhost : 5432 / vk_rideshare ?schema=public
   протокол    польз-ль    пароль      хост        порт    база          схема
```

### 3.2. `VK_APP_SECRET` — ключ, которым подписываются launch-параметры

Для локальной разработки подойдёт **любая непустая строка** — она нужна
только чтобы подписывать и проверять моковые параметры:

```dotenv
VK_APP_SECRET=local-dev-secret-change-me
```

Сгенерировать что-то посерьёзнее:

```bash
node -e "console.log(require('node:crypto').randomBytes(24).toString('base64url'))"
```

Пустым оставлять **нельзя**: приложение запустится, но каждый запрос к API
вернёт `401` с текстом `Защищённый ключ приложения не настроен`.

Для продакшена сюда идёт настоящий защищённый ключ из кабинета
разработчика ВКонтакте — см. [«Приложение во ВКонтакте»](#приложение-во-вконтакте).

### 3.3. `VK_MOCK_LAUNCH_PARAMS` — вход в приложение вне ВКонтакте

Без этой строки приложение откроется, но покажет «Не удалось подтвердить
запуск»: браузер вне фрейма ВКонтакте не получает launch-параметров, и API
честно отвечает `401`.

```dotenv
VK_MOCK_LAUNCH_PARAMS=vk_user_id=1000001&vk_app_id=51234567&vk_platform=desktop_web
```

`vk_user_id` — любой из сид-данных, от `1000001` до `1000010`. От его имени
вы и войдёте. `1000001` — Анна Ковалёва, у неё есть и свои объявления, и
отклики, и отзывы, так что все пять экранов сразу непустые.

> **Проверка подписи при этом не отключается.** Бэкенд берёт эту строку,
> проставляет свежий `vk_ts` и подписывает её вашим же `VK_APP_SECRET`,
> после чего она проходит ровно тот же путь, что настоящая. Ветки
> «пропустить проверку» в коде нет. В продакшене вся эта ветка выключена
> двумя независимыми предохранителями — см. [«Как устроена
> авторизация»](#как-устроена-авторизация).

### Готовый минимальный `.env`

Вот файл целиком, который точно работает. `DATABASE_URL` здесь — для
Postgres, установленного в систему (вариант А из шага 2); для Docker
подставьте `rideshare:rideshare` вместо `postgres:ВАШ_ПАРОЛЬ`.

```dotenv
POSTGRES_USER=
POSTGRES_PASSWORD=
POSTGRES_DB=
POSTGRES_PORT=

DATABASE_URL=postgresql://postgres:ВАШ_ПАРОЛЬ@localhost:5432/vk_rideshare?schema=public

API_PORT=
API_HOST=
NODE_ENV=
CORS_ORIGIN=

VK_APP_ID=
VK_APP_SECRET=local-dev-secret-change-me
VK_MOCK_LAUNCH_PARAMS=vk_user_id=1000001&vk_app_id=51234567&vk_platform=desktop_web

VITE_API_BASE_URL=
```

## Шаг 4. Накатить схему на базу

```bash
npm run db:push
```

Команда читает `apps/api/prisma/schema.prisma` и приводит базу к нему:
создаёт таблицы `users`, `trips`, `trip_requests`, `reviews`, перечисления
и индексы. Если базы ещё нет, команда создаёт её сама — вручную ничего
создавать не нужно.

Успешный вывод (строка про `created` появляется, только если базы не было):

```
Prisma schema loaded from prisma/schema.prisma.
Datasource "db": PostgreSQL database "vk_rideshare", schema "public" at "localhost:5432"

PostgreSQL database vk_rideshare created at localhost:5432

🚀  Your database is now in sync with your Prisma schema. Done in 181ms
```

> `db:push` против `db:migrate`: `db:push` просто синхронизирует схему и
> удобен в разработке. `npm run db:migrate` дополнительно создаёт файл
> миграции в `apps/api/prisma/migrations` — это нужно, когда вы меняете
> схему и хотите повторить изменение на другой машине или в продакшене.
> Для первого запуска достаточно `db:push`.

## Шаг 5. Залить сид-данные

```bash
npm run db:seed
```

Сид детерминирован: одинаковый на любой машине. Он **сначала очищает**
таблицы, поэтому его можно запускать сколько угодно раз — состояние всегда
одно и то же.

Успешный вывод:

```
  Сид выполнен
  ─────────────────────────────────────────
  Пользователей:        10
  Поездок:              36  (ACTIVE 26 / COMPLETED 8 / CANCELLED 2)
  Уникальных маршрутов: 6
  Цены:                 500 – 850 ₽
  Откликов:             46  (PENDING 14 / ACCEPTED 26)
  Отзывов:              33

  Ближайшие активные поездки:
   • Оренбург → Акбулак, ..., пассажир Анна Ковалёва, мест 2/2, 750 ₽
   • Оренбург → Соль-Илецк, ..., водитель Анна Ковалёва, мест 2/2, 600 ₽
   ...
```

Даты поездок считаются от момента запуска сида, поэтому активные поездки
всегда в будущем, а завершённые — в прошлом.

## Шаг 6. Запустить приложение

```bash
npm run dev
```

Поднимаются **два** процесса в одном терминале:

| Процесс | Адрес | Что это |
|---|---|---|
| API | <http://localhost:3000> | Fastify, перезапускается сам при правке кода |
| Фронтенд | <http://localhost:5173> | Vite, горячая перезагрузка |

**На Windows** `npm run dev` не сработает (используется синтаксис `&` из
POSIX-оболочек). Откройте два терминала:

```bash
npm run dev:api    # в первом
npm run dev:web    # во втором
```

### Что должно получиться

Откройте <http://localhost:5173/>.

Ожидаемое:

- заголовок **«Поиск попутчиков»**, под ним панель фильтров;
- в ленте **20 карточек** поездок (первая страница из 26 активных),
  направления — только между Оренбургом, Соль-Илецком и Акбулаком;
  у каждой карточки есть цена в коридоре 500–850 ₽ и время вида 06:30;
- внизу таббар: Поиск · Создать · Мои · Профиль;
- на вкладке «Профиль» — Анна Ковалёва с рейтингом и отзывами;
- в консоли браузера **пусто**.

Быстрая проверка из терминала, не открывая браузер:

```bash
curl -s http://localhost:3000/health
# {"status":"ok"}

curl -s "http://localhost:3000/api/trips?limit=1" | head -c 120
# {"items":[{"id":"seed-active-1","role":"PASSENGER","fromCity":"Оренбург", ...
```

Второй запрос идёт без заголовка `X-Launch-Params` и проходит именно
потому, что сработал моковый режим из шага 3.3.

## Вход под другим пользователем

Три способа, от простого к гибкому.

**1. Поменять `vk_user_id` в `.env`** и перезапустить API:

```dotenv
VK_MOCK_LAUNCH_PARAMS=vk_user_id=1000004&vk_app_id=51234567&vk_platform=desktop_web
```

**2. Сгенерировать полную подписанную строку** и открыть приложение с ней —
перезапускать ничего не нужно:

```bash
npm run gen:launch-params -w @vk-rideshare/api -- --user 1000003
```

Вывод:

```
Launch-параметры для vk_user_id=1000003:

vk_access_token_settings=&vk_app_id=0&vk_are_notifications_enabled=0&...&sign=uchDHs9XFT4R...

Строка подписана локальным VK_APP_SECRET и живёт 24 часа.
```

Откройте `http://localhost:5173/?<вставьте строку>` — приложение
запустится от имени Марии Егоровой. Строка кэшируется в `sessionStorage`,
поэтому переходы внутри приложения её не теряют.

**3. Два пользователя одновременно** — второго откройте в приватном окне
браузера (в обычном они делят `sessionStorage` и перетирают друг друга).
Так удобно проверять сценарий «один откликнулся — другой принял».

## Если что-то пошло не так

| Что видите | Почему | Что делать |
|---|---|---|
| `Некорректная конфигурация окружения — DATABASE_URL обязателен` | Нет `.env` или в нём пустой `DATABASE_URL` | Шаг 3.1 |
| `Некорректная конфигурация окружения — VK_APP_SECRET обязателен при NODE_ENV=production` | `NODE_ENV=production` без ключа | Заполните `VK_APP_SECRET` либо уберите `NODE_ENV` из `.env` |
| `Error: P1001: Can't reach database server at 'localhost:5432'` при `db:push` | Postgres не запущен или указан не тот порт | Проверьте, что сервер работает (служба `postgresql-x64-16` на Windows, `docker compose ps` для контейнера), и сверьте порт в `DATABASE_URL`. Саму базу создавать не нужно — `db:push` создаст её |
| `Docker Desktop failed to start… Virtualization support not detected` | В BIOS/UEFI выключена аппаратная виртуализация (Intel VT-x / AMD-V) либо её запрещает политика компании | Включите её в BIOS (обычно `Intel Virtualization Technology` или `SVM Mode`) и компоненты Windows «Платформа виртуальной машины» и WSL2. Если машина корпоративная и доступа к BIOS нет — **берите вариант А из шага 2**, Docker для этого проекта не обязателен |
| `failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine` | Docker Desktop установлен, но не запущен | Запустите Docker Desktop и дождитесь статуса **Running** в трее, затем повторите команду |
| `password authentication failed for user "postgres"` | В `DATABASE_URL` не тот пароль, который задавался при установке Postgres | Исправьте пароль в `DATABASE_URL`. Забыли — переустановите Postgres или смените пароль через pgAdmin |
| `401 {"code":"UNAUTHORIZED","message":"Заголовок X-Launch-Params отсутствует"}` | Пустой `VK_MOCK_LAUNCH_PARAMS` | Шаг 3.3, затем перезапустите API |
| `401 ... "Защищённый ключ приложения не настроен"` | Пустой `VK_APP_SECRET` | Шаг 3.2 |
| `401 ... "Подпись launch-параметров не совпала"` | Строка в адресе подписана другим ключом | Перегенерируйте: `npm run gen:launch-params` |
| `401 ... "Launch-параметры устарели"` | Строке из адресной строки больше суток | Перегенерируйте её же командой |
| Экран «Не удалось подтвердить запуск» | То же, что две строки выше | См. выше |
| Лента пустая, в консоли `Failed to fetch` / ошибка CORS | Фронтенд открыт с адреса, которого нет в `CORS_ORIGIN` — например, Vite занял порт 5174 | Допишите адрес в `CORS_ORIGIN` через запятую и перезапустите API. По умолчанию разрешены `http://localhost:5173` и `http://127.0.0.1:5173` |
| Лента пустая, ошибок нет | Сид не заливали | `npm run db:seed` |
| Все поездки пропали из ленты через несколько дней | Лента показывает только будущие поездки | `npm run db:seed` пересчитает даты от «сейчас» |
| `EADDRINUSE: address already in use :::3000` | Порт занят | `API_PORT=3001` в `.env` и `VITE_API_BASE_URL=http://localhost:3001/api` |
| `Port 5173 is in use` | Порт занят | Vite сам возьмёт 5174 и напишет об этом; добавьте новый адрес в `CORS_ORIGIN` |
| `fatal: could not create work tree dir 'Labs': Permission denied` при `git clone` | Терминал находится в каталоге, куда вам нельзя писать — обычно `C:\Windows\System32` (cmd «от имени администратора») или корень диска | Перейдите в свою папку и повторите: `cd /d %USERPROFILE%\projects` (cmd) или `cd ~/projects` (macOS, Linux). Администратором запускать не нужно |
| `destination path 'Labs' already exists and is not an empty directory` | Папка от прошлой попытки | Зайдите в неё и продолжите с `git checkout`, либо удалите её и клонируйте заново |
| `Cannot find module '@vk-rideshare/shared'` | Не собран общий пакет | `npm run build -w @vk-rideshare/shared` |
| `Не удалось привести тестовую базу к схеме` при `npm run test` | Схема менялась несовместимо поверх старых тестовых данных | Удалите базу — тесты создадут её заново: `psql -U postgres -c "DROP DATABASE IF EXISTS vk_rideshare_test"` |
| `npm run dev` на Windows ничего не делает | Синтаксис `&` из POSIX-оболочки | `npm run dev:api` и `npm run dev:web` в двух терминалах |
| Запросы уходят на `/api/...` вместо `localhost:3000` | В `VITE_API_BASE_URL` мусор | Оставьте пустым — подставится `http://localhost:3000/api` |

Правку `.env` **фронтенд подхватывает только после перезапуска** Vite:
переменные `VITE_*` вшиваются в бандл на сборке, а не читаются в рантайме.

## Остановить и сбросить

Приложение останавливается `Ctrl+C` в терминале с `npm run dev` — оба
процесса гаснут вместе.

**Вернуть сид-данные в исходное состояние**, базу не трогая, — на любом
варианте из шага 2:

```bash
npm run db:seed
```

**Начать с полностью чистой базы.** Если Postgres стоит в системе:

```bash
# Windows: psql лежит в C:\Program Files\PostgreSQL\16\bin
psql -U postgres -c "DROP DATABASE IF EXISTS vk_rideshare"
npm run db:push && npm run db:seed    # базу создаст сам db:push
```

Если Postgres в Docker:

```bash
docker compose stop        # остановить, данные останутся
docker compose down        # удалить контейнер, данные останутся в томе
docker compose down -v     # удалить вместе с данными
docker compose up -d --wait && npm run db:push && npm run db:seed
```

Посмотреть, что лежит в базе, глазами:

```bash
npm run db:studio     # Prisma Studio; адрес команда печатает сама
```

Порт Prisma Studio выбирает при запуске, поэтому смотрите строку
`Prisma Studio is running at: http://localhost:<порт>` в её выводе. Свой
порт задаётся флагом: `npm run db:studio -w @vk-rideshare/api -- --port 5555`.

# Как устроена авторизация

ВКонтакте передаёт мини-приложению launch-параметры (`vk_user_id`,
`vk_app_id`, `vk_ts`, `sign` и прочие `vk_*`) в query-строке. Фронтенд
запоминает **исходную** строку и шлёт её заголовком `X-Launch-Params` при
каждом запросе к API.

Бэкенд на каждом запросе берёт параметры с префиксом `vk_`, сортирует по
ключу, собирает query-строку, считает от неё HMAC-SHA256 на защищённом
ключе приложения, кодирует в base64url без паддинга и сравнивает с `sign`
константным по времени сравнением. Несовпадение — `401`. Параметры с
`vk_ts` старше 24 часов — тоже `401`.

**Защищённый ключ живёт только в переменной окружения бэкенда.** На
фронтенд он не попадает, в репозиторий не коммитится, в логи не пишется
(заголовок `X-Launch-Params` вырезается из журнала Fastify).

Сессий и куки нет намеренно: подпись проверяется на каждом запросе,
состояние на сервере не нужно.

**Моковый режим выключен в продакшене двумя независимыми
предохранителями:** конфигурация обнуляет `VK_MOCK_LAUNCH_PARAMS` при
`NODE_ENV=production`, и хук авторизации в эту ветку не заходит, если
`isProduction`. Оба покрыты тестами в `apps/api/test/auth.test.ts`.

# Выкатка

## Фронтенд — на хостинг VK Mini Apps

1. Задайте боевой адрес API **до** сборки: значение вшивается в бандл, а не
   читается в рантайме.

   ```dotenv
   VITE_API_BASE_URL=https://api.вашдомен/api
   ```

2. Соберите статику:

   ```bash
   npm run build -w @vk-rideshare/web
   ```

   Результат — `apps/web/dist`. Сборка использует относительные пути
   (`base: './'` в `vite.config.ts`), поэтому работает из любого подкаталога.

   Сборка фронтенда всегда production-режимная и не зависит от `NODE_ENV`
   в общем `.env`: тот файл — конфигурация бэкенда, и `vite.config.ts`
   берёт из него только `VITE_API_BASE_URL`. Иначе `NODE_ENV=development`,
   оставленный в файле с прошлой отладки, тихо уехал бы на хостинг
   development-сборкой React.

3. Залейте каталог на хостинг VK Mini Apps. ВКонтакте даёт для этого CLI
   `@vkontakte/vk-miniapps-deploy` — он кладёт статику на выданный домен и
   разводит staging- и production-версии. В зависимости проекта пакет
   намеренно не добавлен: это инструмент выкатки, а не код приложения.

   ```bash
   npx @vkontakte/vk-miniapps-deploy
   ```

   При первом запуске команда попросит токен и параметры приложения.
   Сверьтесь с актуальной документацией на dev.vk.com: порядок авторизации
   и названия окружений там периодически меняются, а из окружения, где
   писался этот код, сайт был недоступен для проверки.

## Бэкенд — отдельно

Хостинг VK Mini Apps раздаёт только статику, бэкенд разворачивается сам по
себе. Ему нужны `DATABASE_URL`, `VK_APP_SECRET`, `NODE_ENV=production` и

# Правила предметной области

Три правила задаются в `packages/shared` и проверяются дважды: Zod-схемой
на бэкенде и формой на фронтенде. Список закрытый — ни город, ни цена, ни
время вне этих рамок в базу не попадут.

### Направления

Шесть, по три пары в обе стороны:

| Откуда | Куда |
|---|---|
| Оренбург | Соль-Илецк, Акбулак |
| Соль-Илецк | Оренбург, Акбулак |
| Акбулак | Оренбург, Соль-Илецк |

Порядок городов важен: «Оренбург → Акбулак» и «Акбулак → Оренбург» — разные
направления. В форме создания выбор «куда» сужается по выбранному «откуда»,
поэтому несуществующий маршрут нельзя даже собрать. Сам справочник —
`ROUTES` в `packages/shared/src/cities.ts`.

### Цена

Обязательна, целое число от **500 до 850 ₽** за место. Карточек «цена не
указана» в приложении не бывает. Границы — `LIMITS.PRICE_MIN` и
`LIMITS.PRICE_MAX`; фильтр «цена до» в поиске принимает значения из того же
коридора.

### Время выезда

Только по сетке получасов: 00:00, 00:30, 01:00 … 23:30 — 48 слотов в сутки.
В форме это выпадающий список, свободный ввод времени убран. Бэкенд
проверяет момент по UTC: пояса России смещены на целое число часов, поэтому
местные :00 и :30 остаются :00 и :30 и в UTC. Сетка —
`DEPART_TIME_SLOTS` в `packages/shared/src/schedule.ts`.

# API

Все маршруты под префиксом `/api` и требуют заголовок `X-Launch-Params`.
Ошибки всегда одного вида: `{ "error": { "code": "...", "message": "..." } }`.
Фронтенд разбирает `code`, а не текст.

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/session` | Проверяет подпись, обновляет кэш профиля, возвращает его |
| `GET` | `/trips` | Лента: фильтры `from`, `to`, `date`, `role`, `priceMax`, `seatsMin`, курсорная пагинация. Только `ACTIVE` и только будущие |
| `POST` | `/trips` | Создание поездки |
| `GET` | `/trips/:id` | Детали. Все отклики видит только автор, остальные — только свой |
| `PATCH` | `/trips/:id` | Завершить или отменить, только автором |
| `POST` | `/trips/:id/requests` | Отклик |
| `GET` | `/trips/:id/reviewable` | Кому можно оставить отзыв по завершённой поездке |
| `PATCH` | `/requests/:id` | Принять или отклонить, только автором поездки |
| `GET` | `/me/trips`, `/me/requests` | Мои объявления и мои отклики |
| `POST` | `/reviews` | Отзыв |
| `GET` | `/users/:vkUserId` | Публичный профиль, рейтинг, отзывы |

Запись ограничена rate limit'ом, CORS открыт только доменам из
`CORS_ORIGIN`.

### Что гарантируется транзакциями

- **Места не уходят в минус.** Принятие отклика уменьшает `seatsLeft`
  условным `UPDATE ... WHERE "seatsLeft" > 0` в одной транзакции с
  переводом отклика в `ACCEPTED`. Параллельная транзакция встаёт на
  блокировке строки, после её снятия Postgres перепроверяет условие на
  новой версии строки и возвращает `409`. Проверено тестом на пять
  одновременных принятий.
- **Отзыв — один раз на пару автор→адресат** и только участнику
  завершённой поездки; рейтинг пересчитывается в той же транзакции.

# Экраны

| Экран | Что на нём |
|---|---|
| **Поиск** | Фильтры (откуда, куда, дата, роль, цена, мест), карточки поездок, скелетоны, пустое состояние, подгрузка по скроллу |

Тема берётся из клиента ВКонтакте: приложение подписано на событие
`VKWebAppUpdateConfig` и переключает `colorScheme` в VKUI. Вне ВКонтакте
используется системная тема браузера.

### Почему кнопка «Написать» ведёт на профиль

В типах `@vkontakte/vk-bridge` нет метода, открывающего диалог с
пользователем. Выдумывать метод нельзя, поэтому кнопка ведёт на
`https://vk.com/id<vkUserId>` — диалог открывается оттуда штатными
средствами клиента. Если в API ВКонтакте появится подтверждённый способ,
менять нужно только `buildProfileUrl` в `apps/web/src/vk/bridge.ts`.

# Чего в проекте нет намеренно

Оплаты и эквайринга, карт и геокодинга, пуш-уведомлений, админки,
мультиязычности, аналитики, CI-конфигов и Docker-образа приложения.

живёт рядом, в `packages/shared/src/schedule.ts`.

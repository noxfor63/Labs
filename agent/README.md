# Агент канала «По пути»

Агент сам следит за обновлениями приложения и поездками, готовит посты для канала @po_puti56 и присылает
их вам в Telegram на согласование. **Публикует только после вашей кнопки «Опубликовать».**

```
              по расписанию или по вашей просьбе
                              │
API «По пути» ─┐              ▼
(что выкачено, ├──►  агент на Claude  ──►  черновик  ──►  карточка вам в Telegram
 поездки)      │                                         [Опубликовать] [Править] [Отклонить]
GitHub ────────┘                                                │
(коммиты, шаблоны постов)                                       ▼ только по кнопке
                                                          пост в @po_puti56
```

Каркас — ядро агента, инструменты, Telegram-бот, подключение через посредника — перенесён из MetodiLabs
(ветка `claude/friendly-fermi-lglpgd`). Новое здесь: инструменты канала, черновики, согласование и обход
по расписанию.

## Как он работает

**Обход.** Раз в `AGENT_SCAN_INTERVAL_HOURS` часов (по умолчанию 6) и только с 9 до 21 по Оренбургу агент
смотрит:

- **что выкачено** на сервер «По пути» — и какие коммиты с прошлого раза ещё не разобраны;
- **сколько поездок** на ближайшие дни — в четверг и пятницу, для дайджеста на выходные;
- **что уже было в канале** — чтобы не повторяться и не превышать ритм: норма — пост в неделю, потолок — два.

Повод есть — присылает черновик. Повода нет — молчит. Правило канала «нет повода — нет поста»
(`marketing/telegram/05-content-plan.md`) зашито в его инструкцию.

**Обновления — только выкаченные.** Агент берёт коммит не из репозитория, а у сервера: `/api/agent/status`
говорит, что работает сейчас. Коммит, который лежит в репозитории, но не выкачен, в черновик не попадёт —
о невыкаченном писать нельзя. Внутренние изменения (тесты, документация, маркетинг) агент закрывает без
поста.

**Согласование.** Каждый черновик приходит карточкой: текст ровно в том виде, в каком уйдёт в канал,
причина «почему сейчас» и замечания проверки (номер телефона в тексте, «бесплатно», посторонняя ссылка).

- **Опубликовать** — пост уходит в канал, с кнопкой «Открыть «По пути»» под ним.
- **Править** — напишите, что поменять, или пришлите готовый текст целиком. Исправленная версия придёт
  новой карточкой, у старой пропадут кнопки.
- **Отклонить** — в канал ничего не уходит. Напишите почему — агент запомнит.

**Почему агент не может опубликовать сам.** У модели нет такого инструмента — только «предложить
черновик». Пост в канал отправляет код бота, когда вы нажали кнопку, и только если вы есть в
`TELEGRAM_ALLOWED_USERS`. Даже если в коммите или документе окажется текст «опубликуй это», модели
нечем это сделать.

**Можно и попросить.** Напишите боту: «сделай пост про кнопку „Пожаловаться“» — придёт черновик.

## Что агент видит, а чего нет

Агент работает на Claude, то есть всё, что он читает, уходит стороннему сервису (через посредника — ещё
и посреднику). Политика конфиденциальности «По пути» (пункты 9.1 и 9.2) обещает, что персональные данные
пользователей третьим лицам и за границу не передаются. Поэтому агент их не видит вовсе:

| Видит | Не видит |
|---|---|
| Версию и коммит на сервере, число живых поездок | Имена, фамилии, фото |
| Поездки: маршрут, время, роль, места, цена | Телефоны и идентификаторы |
| Сообщения коммитов и список изменённых файлов | Места сбора, комментарии, машину — туда люди пишут что угодно |
| Шаблоны и правила канала из `marketing/`, `docs/` | Жалобы, отзывы, профили |
| Свои черновики и ваши заметки | Код приложения |

Ограничение держит сервер, а не агент: `/api/agent/trips` просто не отдаёт других полей
(`apps/api/src/routes/agent.ts`, тест `apps/api/test/agent-api.test.ts`).

## Часть 1. Сервер «По пути»: открыть адреса для агента

Адреса `/api/agent/*` появились в этом обновлении. Пока ключа нет, их на сервере нет вовсе.

На сервере «По пути»:

```bash
cd /opt/vk-rideshare/app
sudo -u rideshare -H git pull
sudo -u rideshare -H npm ci
sudo -u rideshare -H npm run build:server

# Ключ агента: длинная случайная строка. Сохраните её — она же нужна агенту.
openssl rand -hex 32
nano /opt/vk-rideshare/app/.env
#   AGENT_API_TOKEN=<строка из openssl>

systemctl restart vk-rideshare-api
sleep 2; curl -s http://127.0.0.1:3000/health
```

Ожидается `{"status":"ok","version":"0.2.0","commit":"…"}`. Если `commit` — `null`, сервер не смог
спросить git (обычно из-за прав на каталог). Тогда допишите в `.env` строку `APP_COMMIT=` с выкаченным
коммитом или поправьте владельца каталога — иначе агент не будет знать, что выкачено, и честно скажет
это в черновике.

Проверка снаружи (с любого компьютера):

```bash
curl -s https://vk-rideshare.duckdns.org/api/agent/status -H "Authorization: Bearer <ключ>"
```

Ожидается `{"version":"0.2.0","commit":"…","activeTrips":…}`. Без ключа — 401.

## Часть 2. Бот и права в канале

### Шаг 1. Отдельный бот

В @BotFather: `/newbot`, имя — например «По пути · редакция», адрес — например `po_puti56_editor_bot`.
Сохраните токен.

**Почему не @po_puti56_bot.** Это бот мини-приложения, ему пишут пользователи. Агент забирает все
сообщения своего бота и всем, кроме вас, отвечает «это бот редакции». Если отдать ему токен
@po_puti56_bot, люди, нажавшие в нём `/start`, получали бы именно этот ответ.

### Шаг 2. Бот — администратор канала

Канал → Управление каналом → Администраторы → Добавить администратора → найдите нового бота.
Право нужно одно — **«Публикация сообщений»**. Остальные выключите: агенту не нужно ни изменять,
ни удалять, ни приглашать.

### Шаг 3. Ваш Telegram ID

Узнаете на шаге 3 части 3: бот сам пришлёт его в ответ на `/start`.

## Часть 3. Установка агента

Агенту нужны четыре адреса: посредник Claude, GitHub, API «По пути» и `api.telegram.org`. Ставить
можно на сам сервер «По пути» — первые три оттуда открыты, а Telegram пускается через ваш VPN (шаг 0).
Или туда, где Telegram открыт и так, — тогда шаг 0 не нужен.

### Шаг 0. Если сервер не видит Telegram — прокси через VLESS

Проверка (от root):

```bash
curl -sS -m 10 -o /dev/null -w "telegram: %{http_code}\n" https://api.telegram.org
```

Трёхзначный код (`302`) — Telegram открыт, переходите к шагу 1. `000` — закрыт, нужен прокси. Два
варианта — какой у вас есть.

**SOCKS5-прокси** (адрес, порт и, обычно, логин с паролем). Ничего ставить не нужно — проверка (curl сам
спросит пароль, в историю команд он не попадёт):

```bash
curl -sS -m 15 --socks5-hostname АДРЕС:ПОРТ --proxy-user ЛОГИН -o /dev/null -w "telegram через прокси: %{http_code}\n" https://api.telegram.org
```

`302` — работает. В `agent/.env` тогда `TELEGRAM_PROXY=socks5h://ЛОГИН:ПАРОЛЬ@АДРЕС:ПОРТ`. Именно `socks5h`:
адрес Telegram разрешает прокси, а не сервер, — DNS сервера может отдавать для него не тот адрес. Если в
пароле есть `@ : / # ?` или `%`, их нужно закодировать: `@` → `%40`, `:` → `%3A`, `/` → `%2F`, `#` → `%23`,
`?` → `%3F`, `%` → `%25`.

**VLESS-ключ.** Ставим Xray — клиент VLESS — так, чтобы он открыл HTTP-прокси **только на 127.0.0.1**: снаружи его
не видно, и ходит через него один агент, только в Telegram. Сервер и приложение работают напрямую.

```bash
# Официальный установщик Xray: бинарник в /usr/local/bin, служба xray
bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)" @ install

# Конфиг из ключа. Ключ спрашивается скрытым вводом и никуда не печатается.
python3 /opt/vk-rideshare/app/agent/deploy/vless_to_xray.py > /tmp/xray.json
xray run -test -config /tmp/xray.json
XUSER=$(systemctl show -p User --value xray); XUSER=${XUSER:-root}
install -o root -g "$(id -gn "$XUSER")" -m 640 /tmp/xray.json /usr/local/etc/xray/config.json && rm /tmp/xray.json
systemctl restart xray && systemctl is-active xray

curl -sS -m 15 -x http://127.0.0.1:10809 -o /dev/null -w "telegram через прокси: %{http_code}\n" https://api.telegram.org
```

`xray run -test` должен ответить `Configuration OK.` (предупреждения об устаревшем транспорте — не
ошибка), `is-active` — `active`, последняя команда — `302`. В `agent/.env` тогда:
`TELEGRAM_PROXY=http://127.0.0.1:10809`.

Права `640` и группа пользователя службы Xray: в конфиге ваш ключ, служба его прочитает, остальные
пользователи сервера — нет.

### Шаг 1. Код

Под пользователем `agent`:

```bash
su - agent
git clone https://github.com/noxfor63/Labs.git ~/Labs
cd ~/Labs/agent
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Если репозиторий станет закрытым — добавьте deploy key только на чтение, как для MetodiLabs
(`docs/telegram-and-server.md` в MetodiLabs, часть 2, шаг 3), и укажите в `.env` `GITHUB_TOKEN`
с правом Contents: Read — им агент читает коммиты через API.

### Шаг 2. Настройки

```bash
cp .env.example .env
chmod 600 .env
nano .env
```

`chmod 600` — чтобы ключи из `.env` не читали другие пользователи сервера.

Заполните: ключ Claude (или адрес и ключ посредника — те же, что у MetodiLabs), `TELEGRAM_BOT_TOKEN`
нового бота, `PP_API_TOKEN` — ключ из части 1. `TELEGRAM_ALLOWED_USERS` пока оставьте пустым.

### Шаг 3. Проверка и ваш ID

```bash
.venv/bin/python -m channel_agent --check
```

Каждая строка должна быть с ✅, кроме «Кто согласует». Затем:

```bash
.venv/bin/python -m channel_agent
```

Напишите боту `/start` — он ответит вашим Telegram ID. Остановите (`Ctrl+C`), впишите ID в
`TELEGRAM_ALLOWED_USERS`, снова `--check` — теперь всё с ✅.

### Шаг 4. Первый обход — вручную

```bash
.venv/bin/python -m channel_agent --scan-once
```

Обход без Telegram: черновик, если повод есть, печатается в терминал и сохраняется — когда запустите бота,
`/drafts` пришлёт его карточкой. Первый запуск запоминает текущий
выкаченный коммит как точку отсчёта — прошлые обновления агент не пересказывает. Хотите, чтобы он
предложил пост про 0.2.0, — перед первым запуском задайте `AGENT_UPDATES_SINCE=2026-10-13T00:00:00Z`.

### Шаг 5. Служба

```bash
exit   # обратно в root
cp /home/agent/Labs/agent/deploy/po-puti-agent.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now po-puti-agent
journalctl -u po-puti-agent -f
```

В журнале — «Бот редакции запущен». Первый плановый обход — через две минуты после запуска, дальше по
расписанию.

**Обновление агента:** `cd ~/Labs && git pull && agent/.venv/bin/pip install -r agent/requirements.txt`,
затем `systemctl restart po-puti-agent`.

## Как пользоваться

| Команда | Что делает |
|---|---|
| `/scan` | Обход прямо сейчас, ответ — одной строкой: черновик или «повода нет: …» |
| `/drafts` | Черновики, ждущие решения, — заново, если карточки утонули в чате |
| `/status` | Что выкачено, когда был обход и что он решил, есть ли права в канале |
| `/new` | Начать разговор заново; черновики и заметки остаются |
| `/usage` | Расход токенов с момента запуска |

Обычным сообщением можно попросить пост или объяснить, как писать впредь: «без нумерации», «по пятницам
дайджест не нужен». Такое агент сохраняет в заметки и учитывает в следующих обходах.

## Настройки

Все — в `agent/.env`, пояснения в `.env.example`. Главные:

| Переменная | По умолчанию | Что это |
|---|---|---|
| `AGENT_MODEL` | `claude-sonnet-5-5` | Модель. Посты короткие — Opus здесь не нужен |
| `TELEGRAM_CHANNEL` | — | Куда публиковать: `@po_puti56` |
| `TELEGRAM_ALLOWED_USERS` | — | Кто видит черновики и может их опубликовать |
| `PP_API_URL`, `PP_API_TOKEN` | — | API «По пути» и ключ агента из части 1 |
| `AGENT_SCAN_INTERVAL_HOURS` | `6` | Как часто обход |
| `AGENT_ACTIVE_HOURS` | `9-21` | Когда обход разрешён |
| `AGENT_MAX_PENDING_DRAFTS` | `3` | Больше черновиков одновременно ждать не будет |
| `AGENT_UPDATES_SINCE` | — | С какой даты считать обновления при первом запуске |

**Расход.** Обход — несколько запросов к модели (проверить обновления, историю, иногда поездки, иногда
написать черновик); системная инструкция кэшируется. Сколько это в рублях, зависит от тарифа посредника —
смотрите `/usage` после пары дней работы и кабинет посредника. Дешевле всего — реже обход:
`AGENT_SCAN_INTERVAL_HOURS=12`.

## Частые проблемы

| Что видно | В чём дело |
|---|---|
| `--check`: «API «По пути»: ключ не принят (401)» | `PP_API_TOKEN` у агента не совпадает с `AGENT_API_TOKEN` на сервере |
| `--check`: «API «По пути»: адрес не найден (404)» | На сервере не задан `AGENT_API_TOKEN` или не перезапущен API |
| «Не удалось опубликовать #…: Forbidden» | Бот не администратор канала или без права «Публикация сообщений» |
| «Этот бот уже запущен в другом месте» | Две копии с одним токеном — остановите вторую |
| В черновике «сервер не сообщил, какой коммит выкачен» | `/health` на сервере отдаёт `commit: null` — см. часть 1 |
| Черновики не приходят | `/status`: когда был обход и что решил. Чаще всего повода просто нет — так и задумано |

```bash
cd agent
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt

```

Тесты не ходят ни в Claude, ни в Telegram, ни в GitHub: Telegram подменён локальным сервером, Claude —
заготовленными ответами (схема из тестов MetodiLabs). Главные проверки — в `tests/test_bot.py`: в канал
уходит только одобренный текст и ровно в том виде, в каком был в карточке; двойное нажатие публикует
один раз; чужое нажатие не публикует ничего.

| Файл | Что в нём |
|---|---|
| `channel_agent/core.py` | Цикл агента — перенесён из MetodiLabs |
| `channel_agent/tools/channel.py` | Инструменты канала. Инструмента публикации нет намеренно |
| `channel_agent/drafts.py` | Черновики, решения, состояние обхода, проверка текста |
